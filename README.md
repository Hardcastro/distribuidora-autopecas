# Anhanguera Autopeças

> **Resumo em português:** site fictício de uma distribuidora de autopeças onde o visitante diz o carro (montadora, modelo, ano, motor) e recebe só as peças compatíveis — a busca resolve uma junção real entre duas tabelas, não um filtro de categoria. Todo o estado do filtro vive na URL e é resolvido no servidor: o link é o produto final desta peça, com preview de Open Graph gerado dinamicamente por filtro. O catálogo fala com uma interface única que troca de fonte de dado (CSV versionado ou um ERP simulado com paginação, token e falhas) por variável de ambiente, sem o site saber a diferença.

A fictional auto parts distributor whose core feature is compatibility lookup by vehicle — not a product catalog with filters bolted on. Built as a portfolio piece to demonstrate a real many-to-many join, URL-as-state architecture, and a swappable data-source layer behind one interface.

## What this is

Anhanguera Autopeças is a fictional light-vehicle parts distributor in Osasco/SP. The site has four routes (home, parts search, part detail, service info) and shares the portfolio's visual signature — "clay + glass, canvas claro" — with [contabilidade-institucional](../contabilidade-institucional) and [restaurante-cardapio-planilha](../restaurante-cardapio-planilha). The home page is organized around a single interaction — pick a vehicle, watch the result change — instead of the hero-and-cards structure of the first piece or the dense menu list of the second. All content, the company, and the part brands are fictional; see [site.config.ts](./site.config.ts) for contact details and copy.

## Visual identity

The mark ([`components/base/Logo.tsx`](./components/base/Logo.tsx)) is a wrench closing over an "A" — a counter tool, not a monogram — drawn as a single SVG path so it holds up from a 32px header lockup to a 180px Apple touch icon, and rebuilt in plain divs for the Satori-rendered `icon.tsx` / `apple-icon.tsx` / `opengraph-image.tsx`. Same clay treatment as the rest of the portfolio — no separate brand system, no new colors.

## Stack

- **Next.js 15** — App Router, TypeScript in strict mode
- **Tailwind CSS v4** — CSS-first configuration (`@theme` block in `app/globals.css`, no `tailwind.config.js`)
- **Inter** — via `next/font/google`
- Hand-written inline SVG icons — no icon library
- Hand-written CSV parser ([`lib/csv.ts`](./lib/csv.ts)) — no CSV parsing dependency, no search library (filter and search run in plain code, server-side)
- No other runtime dependencies. Photos are a deliberate, scoped exception for the category shortcuts and the home top band — see [Photo credits](#photo-credits)

## Running it locally

```bash
npm install
npm run dev
```

Open [http://localhost:3002](http://localhost:3002) (or whichever port `next dev` picks). The site works end to end with **zero configuration**: without any `.env`, `FONTE` defaults to `csv` and the site reads the versioned [`pecas.csv`](./pecas.csv) and [`aplicacoes.csv`](./aplicacoes.csv) — cloning and running never depends on a secret or a live system.

### Regenerating the sample data

The ~1,245 parts and ~8,350 compatibility rows were generated by [`scripts/gerar-dados.mjs`](./scripts/gerar-dados.mjs) from a catalog of 33 real Brazilian-market vehicle models (with real generations, year ranges and engine families) crossed with fictional part brands. Re-run it any time with:

```bash
node scripts/gerar-dados.mjs
```

It's deterministic (seeded PRNG) — re-running it without editing the script reproduces the exact same files.

### Environment variables

See [.env.example](./.env.example).

| Variable | Required | Purpose |
| --- | --- | --- |
| `FONTE` | No | `csv` (default) or `erp`. Chooses which adapter in [`lib/fonte/`](./lib/fonte) answers `getCatalogo()`. |
| `ERP_BASE_URL` | Only for `FONTE=erp` | Base URL of the simulated ERP, e.g. `http://localhost:3002/api/erp` in dev. |
| `ERP_TOKEN` | Only for `FONTE=erp` | Bearer token the simulated ERP expects. Defaults to `anhanguera-dev-token` on both sides if unset. |

### Trying the simulated ERP directly

The ERP lives inside this same app at `/api/erp/*` — it's what `FONTE=erp` talks to over HTTP, paginated, with a bearer token, exactly like a real third-party system:

```bash
# 401 — no token
curl -i "http://localhost:3002/api/erp/pecas?pagina=1&por_pagina=5"

# 200 — with token, paginated
curl -s "http://localhost:3002/api/erp/pecas?pagina=1&por_pagina=5" \
  -H "Authorization: Bearer anhanguera-dev-token" | head -c 600

# next page
curl -s "http://localhost:3002/api/erp/pecas?pagina=2&por_pagina=5" \
  -H "Authorization: Bearer anhanguera-dev-token"

# simulated failure modes, all still 2xx/4xx/5xx handled — never crash the caller
curl -s "http://localhost:3002/api/erp/pecas?simular=erro" \
  -H "Authorization: Bearer anhanguera-dev-token"          # 500
curl -s "http://localhost:3002/api/erp/pecas?simular=lento" \
  -H "Authorization: Bearer anhanguera-dev-token"          # 6s delay
curl -s "http://localhost:3002/api/erp/pecas?simular=malformado" \
  -H "Authorization: Bearer anhanguera-dev-token"          # truncated JSON

# the aplicacoes endpoint follows the same contract
curl -s "http://localhost:3002/api/erp/aplicacoes?pagina=1&por_pagina=5" \
  -H "Authorization: Bearer anhanguera-dev-token"
```

To see the site itself run against the ERP adapter, with automatic fallback to the CSV on failure:

```bash
FONTE=erp ERP_BASE_URL=http://localhost:3002/api/erp npm run dev
```

Then visit `/pecas?montadora=volkswagen&modelo=gol&ano=2011&motor=1.0-8v-ea111` — same result as `FONTE=csv`. Point `ERP_BASE_URL` at a URL with `?simular=erro` baked in (or kill the dev server mid-request) to see the page fall back to the CSV with a discreet "catalog might be stale" notice instead of a 500.

## What this project demonstrates

**Compatibility as a real join is the centerpiece.** Everything else — the URL-as-state architecture, the swappable data source — exists to make that join something a vendor can actually hand to a mechanic as a link.

- **The junction, not a filter.** [`lib/catalogo.ts`](./lib/catalogo.ts)'s `buscarPecas()` intersects the parts table against the applications table on montadora + modelo + year-inside-range + motor, all four at once. Change only the engine and the result set changes even though the model and year didn't move; change only the year across a generation boundary and it changes too — both are checkable directly in the URL (see the proof commands below). `/peca/[codigo]` walks the same relation in reverse, grouping every vehicle a part fits by montadora and modelo with a readable year range.
- **The URL is the entire state, resolved server-side.** `/pecas` reads `searchParams` on the server — nothing is filtered in a `useEffect` against client-only state. Paste a filtered link in a new tab, another phone, or two days later, and it renders identically. "Copy link" and "Send on WhatsApp" ([`components/base/ShareBar.tsx`](./components/base/ShareBar.tsx)) both just read `window.location` at the moment they're clicked.
- **A per-filter Open Graph preview, not a static one.** `opengraph-image.tsx` only receives route `params`, not `searchParams` — it can't see the filter. So `/pecas` sets `generateMetadata({ searchParams })` to point `openGraph.images` at a plain route handler, [`/og/pecas`](./app/og/pecas/route.tsx), which reruns the same `buscarPecas()` query and draws "23 peças · Gol 1.0 8V EA111 2011" with `ImageResponse`. Paste a filtered `/pecas` link into any chat app and the preview says what's actually inside.
- **The catalog doesn't know where the data comes from.** [`lib/fonte/index.ts`](./lib/fonte/index.ts) exposes one function, `getCatalogo()`. Behind it, [`lib/fonte/csv.ts`](./lib/fonte/csv.ts) reads the versioned files and [`lib/fonte/erp.ts`](./lib/fonte/erp.ts) talks to a paginated, token-gated HTTP API with a timeout and one retry before giving up. Switching is an environment variable, not a code change — and a failed ERP call falls back to the CSV with a visible (but discreet) staleness notice instead of a 500.
- **Search tolerant of how a code actually gets typed.** `JP-4412`, `jp4412`, and `JP 4412` all resolve to the same part — codes are normalized to uppercase-alphanumeric-only before comparison ([`normalizarCodigo`](./lib/format.ts)). Text search strips accents both sides, so `suspensao` matches `Suspensão`.
- **Rows that don't parse don't take the page down.** A part row missing a code or name is dropped, not crashed on. An unrecognized category sorts to the end of the list instead of disappearing. A part with zero registered applications stays fully searchable by code — compatibility data being incomplete never makes the part itself vanish.
- **A selector-first layout, not a repeat of the other two pieces.** The home page's center of gravity is the cascading vehicle selector ([`components/base/VehicleSelector.tsx`](./components/base/VehicleSelector.tsx)) — montadora → modelo → ano → motor, deliberately photo-free so it stays the fastest thing on the page. Every change is a real navigation (`router.push`, not local state), so the browser's back button undoes one filter step at a time.
- **The "clay + glass" system stays disciplined.** The sticky header and the photo band under it are the only two `backdrop-filter` elements on any given route — well under the self-imposed budget of three. The parts list itself is purely typographic: code, name, position and price carry the row, no photo, no placeholder, styled after a printed technical catalog.

## Fictional data disclaimer

Anhanguera Autopeças is not a real company. Vehicle models, generations, year ranges and engine names are real (Brazilian market, for the catalog to read as plausible), but every part brand — Vergueiro, Tietê, Pirajuçara, Jaraguá, Ibirapuera, Anhembi — is invented. Any resemblance to an existing parts brand is coincidental; none is intentional. Prices, stock, and the ERP itself are simulated for demonstration only.
